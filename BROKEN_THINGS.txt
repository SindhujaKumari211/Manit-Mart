MANIT-MART - BROKEN THINGS REPORT
Generated by manual code read-through (backend, frontend, mobile).
==================================================================

CRITICAL BUGS (things that fail at runtime)
--------------------------------------------

1. [frontend/src/pages/Cart.jsx:62-84] "Place Order" button on the Cart page will
   ALWAYS fail. handlePlaceOrder() POSTs { product, quantity, totalPrice, paymentMethod }
   to /orders, but backend/controllers/orderController.js createOrder() requires
   { productId, quantity, deliveryAddress, phone } and immediately 400s with
   "All fields are required" if any are missing ("product" != "productId", and
   deliveryAddress/phone are never sent at all). Checkout from the Cart page is
   completely non-functional; only the "Buy Now" flow on ProductDetail.jsx (which
   sends the correct field names) can ever create an order.

2. [frontend/src/pages/addProduct.jsx:45-53, 68-76] Gallery/camera photo upload
   converts the image to a base64 data URL (often several hundred KB to a few MB)
   and sends it as JSON in the "image" field via API.post("/products", ...).
   backend/app.js:15 uses app.use(express.json()) with no size limit, so Express's
   default 100kb body limit applies. Any real photo taken via camera/gallery will
   cause the POST to fail with "413 Payload Too Large", making product creation
   with real photos broken (only small/compressed images or manually pasted URLs
   work). Same risk applies to Profile.jsx's picture upload (partially mitigated
   there by a client-side 5MB check, which does NOT prevent the 100kb server limit
   from rejecting it anyway).

3. [frontend/src/components/Navbar.jsx:187-195] and
   [frontend/src/components/productCard.jsx:84-90] Both link to "/my-products",
   but frontend/src/App.jsx defines no such route. Clicking "My Products" in the
   navbar dropdown renders a blank page (React Router has no matching <Route>).

4. [frontend/src/pages/Orders.jsx:124, 129] Renders order.buyer.username and
   order.seller.username. backend's User model (backend/models/User.js) has no
   "username" field, only "name", and orderController populates buyer/seller with
   "name email phone" (not username). Both will always render as blank/undefined
   in the Orders list ("Buyer: " / "Seller: " with nothing after it).

5. [manit-marketplace-mobile] The mobile app has two competing, inconsistent API
   clients that are both effectively dead code:
   - src/services/api.js baseURL = "http://localhost:5000" or
     "http://192.168.0.116:5000" (MISSING the "/api" prefix entirely — any call
     like API.get("/products") would hit http://.../products, a 404, since the
     backend only mounts routes under /api/*).
   - src/api/axios.js baseURL = "http://192.168.0.116:5000/api" (correct prefix,
     but hardcoded to one developer's LAN IP).
   Neither file is actually imported anywhere in the app/ or components/ folders
   (grep found zero usages) — the mobile app is still just the stock Expo tab
   template; none of the marketplace screens (product list, cart, wishlist,
   orders, auth) have been implemented yet, despite src/screens and
   src/components existing as empty placeholder folders.

MEDIUM ISSUES (silent failures / bad data, no crash)
-----------------------------------------------------

6. [backend/middleware/authMiddleware.js:13-19] If a JWT is valid but the user it
   references has been deleted from the DB, User.findById(decoded.id) resolves to
   null, req.user is set to null, and next() is still called (no check for
   !req.user). Every downstream controller that does req.user._id (createProduct,
   updateProduct, deleteProduct, markAsSold, cart/wishlist/order controllers) will
   then throw an uncaught TypeError ("Cannot read properties of null"), which is
   only caught because each controller wraps its body in try/catch and returns a
   generic 500 — so the failure mode is a confusing 500 instead of the intended
   401 "user not found".

7. [frontend/src/pages/EditProduct.jsx:38-42] fetchData() spreads the ENTIRE
   product API response (`...productRes.data`) into local form state, including
   fields the schema does not expose in the edit form: _id, seller (a populated
   object {_id, name, email, phone, address} instead of a plain ObjectId string),
   isSold, rating, createdAt, updatedAt, __v. On submit, the whole `form` object
   (including that populated seller object and other extraneous fields) is PUT
   back to /products/:id. It happens to not crash (Mongoose's ObjectId caster
   special-cases objects with an _id property), but it is fragile: any future
   change to what getSingleProduct populates, or to strict-mode schema behavior,
   silently changes what gets written back to the product's seller field.

8. [backend/controllers/productController.js:69-77] getProducts() has the exact
   same "isSold filter override" if-block duplicated back-to-back (lines 70-72
   and 75-77 do the identical `filter.isSold = req.query.isSold === "true"`).
   Dead duplicate code — harmless but indicates leftover/unfinished edits.

9. [.env:2] MONGO_URI has no explicit database name in the connection string
   (mongodb+srv://.../?appName=Cluster0 — nothing between the last "/" and "?"),
   so Mongoose/MongoDB will default to a database named "test". If this wasn't
   the intended DB name, data could be going to the wrong database, and the
   .env file has live cluster credentials committed in plaintext (should be
   gitignored and rotated).

10. [frontend/src/pages/EditProduct.jsx] Unlike addProduct.jsx, this page offers
    only a plain "Image URL" text field — no gallery/camera upload option — so a
    product originally listed with a camera photo (base64 data URL) cannot be
    conveniently re-photographed on edit; the existing base64 string is shown as
    the input value, which is technically editable but not a usable UX for that
    case.
